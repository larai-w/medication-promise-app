## 1. アプリ概要

**Drug and Oath**（ドラッグ・アンド・オース）は、服薬管理アプリ。

- **ユーザー像**: 在宅介護の家族介護者、または施設入居者本人
- **コア価値**: 「今日飲んだか」を一秒で記録・確認できる
- **チャネル**: Web（スマホブラウザ）+ Alexa（音声）
- **インフラ**: Next.js / AWS DynamoDB / Alexa Skill Lambda

服薬タイミング: 朝 / 昼 / 晩 / 夜8時 / 夜9時（5回/日）

## 2. Fable が使う Claude Code スキル

Fable（Claude Fable 5）がこのプロジェクトを開発する際に活用するスキル一覧。

### 2-1. `/init`
**用途**: 新しい開発者や Fable が初めてリポジトリに入ったとき、`CLAUDE.md` を自動生成してコードベースのコンテキストを整備する。

**このプロジェクトでの具体的な使い方**:
- `drug-and-oath/web/` と `drug-and-oath/alexa/` の二層構造を記述
- DynamoDB のテーブル設計（PK/SK フォーマット）をドキュメント化
- 服薬タイミング定数と環境変数の一覧を自動抽出

---

### 2-2. `/run`
**用途**: アプリを実際に起動してブラウザで動作確認する。UIの変更が正しく動いているか、ゴールデンパスを手動テスト。

**このプロジェクトでの具体的な使い方**:
- `cd drug-and-oath/web && npm run dev` で Next.js を起動
- 今日の服薬画面・月次画面・PDF出力を実際に操作して確認
- Alexa Lambda は `npm run zip` でビルドし、Alexa シミュレーターでテスト
- モーダルの開閉・削除確認・エラー表示を目視チェック

---

### 2-3. `/verify`
**用途**: コードを変更した後、その変更が意図通りに動いているかを実際の動作で検証する。

**このプロジェクトでの具体的な使い方**:
- 服薬記録の追加 → DynamoDB への書き込み → 一覧表示のラウンドトリップ確認
- Alexa Reminders API の権限フロー（パーミッション未付与 → カード表示 → 再設定）の検証
- PDF ダウンロードが正しい月・正しいフォント（NotoSansJP）で出力されるか確認
- 月次画面の前月/次月ナビゲーションが日付境界で正しく動くか確認

---

### 2-4. `/code-review`
**用途**: 変更差分の正確性バグ・再利用性・効率性を多角的にレビューする。

**このプロジェクトでの具体的な使い方**:
- Alexa `index.mjs` の DynamoDB 重複ロジック（`dynamodb.mjs` との重複）を指摘・修正提案
- API ルートのエラーハンドリング漏れを検出（現状: クライアント側に `confirm()` しかない）
- `PUT /api/records/[id]` の入力バリデーション不足を発見
- `/code-review ultra` で深いレビュー（型安全性・DynamoDB の PK/SK 設計の堅牢性）

---

### 2-5. `/security-review`
**用途**: 医療・健康データを扱うため、OWASP Top 10 を中心にセキュリティ脆弱性を検査する。

**このプロジェクトでの具体的な使い方**:
- DynamoDB アクセスキーの `.env.local` 漏れリスク確認
- API ルートの認証・認可欠如（現状: `USER_ID` が固定の `default-user`）を指摘
- Alexa Lambda の環境変数注入リスク確認
- `confirm()` による削除フローの CSRF 脆弱性チェック
- 将来のマルチユーザー化に向けた認証設計への提言

---

### 2-6. `/simplify`
**用途**: 動くコードをシンプル・効率的に整理する。バグ修正ではなく品質向上。

**このプロジェクトでの具体的な使い方**:
- `alexa/index.mjs` の重複 DynamoDB ロジックを `dynamodb.mjs` に統合
- `MainScreen.tsx` と `RecentList.tsx` の重複した日付フォーマット処理を共通化
- 5つの `Record*Intent` ハンドラを タイミングマップ駆動で統一
- `TIMING_DEFAULTS` を Single Source of Truth として徹底活用

---

### 2-7. `/loop`
**用途**: 繰り返し発生するタスクを定期実行する。

**このプロジェクトでの具体的な使い方**:
- `/loop 10m /verify` で開発中に10分ごとに動作確認を自動実行
- DynamoDB への書き込みポーリングテスト（Alexa Lambda のスモークテスト）
- CI の GitHub Actions 結果を監視

---

### 2-8. `/schedule`
**用途**: クラウドエージェントをcronスケジュールで定期実行する。

**このプロジェクトでの具体的な使い方**:
- 毎朝8時に「今日の未記録タイミング」をチェックして通知するルーティン
- 月次PDFの自動生成・保存スケジュール
- Alexa Reminders の設定確認バッチ（権限が外れていないか監視）

---

### 2-9. `/review`（PR レビュー）
**用途**: GitHub Pull Request を包括的にレビューする。

**このプロジェクトでの具体的な使い方**:
- Alexa リマインダー PR（現在の未コミット変更）をマージ前にレビュー
- DynamoDB スキーマ変更 PR の安全性確認
- Next.js バージョンアップ PR の破壊的変更チェック

---

### 2-10. `/fewer-permission-prompts`
**用途**: 頻繁に使うコマンドの権限プロンプトを削減してスムーズに開発。

**このプロジェクトでの具体的な使い方**:
- `npm run dev`・`npm run build`・`npm run lint` を自動許可リストに追加
- `git status`・`git diff` を読み取り専用として自動許可
- AWS CLI コマンド（DynamoDB ローカルテスト用）の許可設定

## 3. ユーザーストーリー（詳細）

| ペルソナ | 説明 |

### エピック 1: 今日の服薬を記録・確認する

#### Story 1-1: 今日の服薬状況を一目で把握したい

```
As Aさん（介護者）,
I want 今日の5回の服薬タイミングを一画面で確認したい,
so that 飲み忘れがないかすぐわかり、安心して他の介護に集中できる。
```

**受け入れ条件**:
- [ ] `/` を開いたとき、今日の日付が表示される
- [ ] 朝・昼・晩・夜8時・夜9時の5タイミングが常に表示される
- [ ] 記録済みのタイミングは視覚的に区別できる（チェック済みスタイル）
- [ ] 未記録タイミングはワンタップで記録できる
- [ ] 画面はスマホ縦持ちで全要素が見える（スクロール最小限）

**見積もりサイズ**: M（実装済み。ポリッシュ対象）

---

#### Story 1-2: ワンタップで服薬を記録したい

```
As Aさん（介護者）,
I want 服薬したタイミングをタップ一つで記録したい,
so that 忙しい介護の合間でも記録漏れなく続けられる。
```

**受け入れ条件**:
- [ ] 各タイミングボタンをタップするとデフォルト時刻で即記録される
- [ ] 記録後、ボタンが「記録済み」に変わる（1秒以内）
- [ ] API エラー時はトースト通知でフィードバックする（現状: エラーハンドリングなし）
- [ ] 同じタイミングを二重記録しようとした場合は警告する
- [ ] オフライン時はキューに積んで復帰後に送信する（将来対応）

**見積もりサイズ**: M（エラーハンドリング追加が必要）

```
As Aさん（介護者）,
I want 誤って記録した服薬を編集または削除したい,

```

**受け入れ条件**:

- [ ] 編集モーダルで日付・タイミング・時刻・メモを変更できる

- [ ] 編集・削除後は一覧がリアルタイムで更新される

**見積もりサイズ**: M（削除UI の改善が必要）

## 4. 開発戦略

### フェーズ構成

```
Phase 0 (完了済み)  → 基本機能の実装
Phase 1 (〜2026-08) → 品質固め・本番化
Phase 2 (〜2026-10) → UX改善・Alexa強化
Phase 3 (〜2027-01) → スケール対応・マルチユーザー化
```

---

### Phase 1: 品質固め・本番化（優先度高）

**目標**: 現在の機能を安全・安定して本番運用できる状態にする。

| タスク | 優先度 | サイズ |
|--------|--------|--------|
| Alexa リマインダー変更をテスト・コミット・デプロイ | P0 | M |
| Alexa DynamoDB 重複ロジックを `dynamodb.mjs` に統合 | P0 | S |
| API エラーハンドリング（クライアント側トースト通知） | P0 | S |
| 削除確認を `confirm()` からモーダルに変更 | P1 | S |
| CI ワークフローを GitHub にプッシュして有効化 | P0 | S |
| main ブランチ保護ルール設定 | P1 | S |
| API ルートのスモークテスト追加 | P1 | M |
| 環境変数の Secrets Manager 管理 | P1 | M |

**技術的負債の解消優先順位**:
1. Alexa 重複ロジック（バグリスクが高い）
2. `confirm()` 削除確認（UX・安全性）
3. クライアント側エラーハンドリング（信頼性）

---

### Phase 2: UX改善・Alexa強化（〜2026-10）

| タスク | 優先度 | サイズ |
|--------|--------|--------|
| リマインダー応答時の自動記録（Story 3-3） | P1 | L |
| PDF にメモ・患者名を含める | P1 | S |
