# エージェント運用ワークフロー — Fable司令塔 + Opus/Sonnet実働

作成日: 2026-07-09

このリポジトリには「Fable が戦略・タスクを立案し、Opus / Sonnet が実装する」体制が
設定済みです。`.claude/agents/` がリポジトリにコミットされているため、
**誰がクローンしても同じ体制がそのまま使えます。**

---

## 役割分担

| モデル | 役割 | 呼び出し方 |
|--------|------|-----------|
| **Fable 5** | 司令塔。戦略立案・タスク分解・作業指示・結果レビュー | メイン会話（`/model` で Fable を選択） |
| **Sonnet** | 定型実装。バグ修正・UI改善・小規模リファクタ・ドキュメント | `implementer` エージェント |
| **Opus** | 複雑実装。認証基盤・スキーマ移行・大規模機能・高リスク変更 | `senior-implementer` エージェント |

モデルの割り当ては `.claude/agents/*.md` の frontmatter（`model:` 行）で固定されているので、
呼び出す側が意識しなくても正しいモデルが使われます。

---

## 仕組み

```
あなた（ユーザー）
  ↓ 要望を伝える
Fable 5（メイン会話 = オーケストレーター）
  ├── 戦略・タスク立案（docs/TASKS.md 更新）
  ├── タスクごとに適切なワーカーを選んで委譲
  │     ├── 定型 → Agent tool で implementer（Sonnet）を起動
  │     └── 複雑 → Agent tool で senior-implementer（Opus）を起動
  ├── ワーカーの成果物をレビュー
  └── 結果をあなたに報告
```

- ワーカーは**毎回まっさらな状態で起動**します。会話の文脈を知らないため、
  Fable が委譲時に「どのファイル・何の受け入れ条件・何を報告するか」を
  プロンプトに全部書いて渡します（各エージェント定義に基本ルールは記載済み）
- ワーカーの最終報告は Fable に返り、Fable がレビューしてからあなたに要約します

## 使い方

### 1. セッション開始

```bash
cd drug-and-oath        # 必ず Git リポジトリ側で起動する
claude
```

メイン会話のモデルを Fable にする（初回のみ。デフォルト保存される）:

```
/model
→ Fable 5 を選択
```

### 2. 依頼の例

**タスク立案から任せる場合:**
> 「次のスプリントのタスクを立てて、実装できるものはワーカーにやらせて」

**特定タスクを指定する場合:**
> 「docs/TASKS.md の T11 を implementer にやらせて」
> 「Cognito 認証（T23）を senior-implementer に設計から任せて」

**並列で進める場合:**
> 「T11 と T12 を別々のワーカーで並行してやらせて」

### 3. Fable がやること（自動）

1. タスクの複雑さを判断して Sonnet / Opus を選ぶ
2. 受け入れ条件・対象ファイル・検証手順を含む指示文を作って委譲
3. 成果物をレビュー（必要なら差し戻し）
4. `docs/TASKS.md` のステータスを更新して報告

## エージェント定義ファイル

| ファイル | モデル | 担当 |
|---------|--------|------|
| `.claude/agents/implementer.md` | Sonnet | 定型実装・バグ修正・UI・ドキュメント |
| `.claude/agents/senior-implementer.md` | Opus | 認証・スキーマ移行・大規模機能・高リスク変更 |

### カスタマイズ方法

- ワーカーを追加したい: `.claude/agents/` に新しい `.md` を作る
  （frontmatter に `name` / `description` / `model` を書き、本文にシステムプロンプトを書く）
- モデルを変えたい: frontmatter の `model:` を `sonnet` / `opus` / `haiku` に変更
- プロジェクトルールを変えたい: 各ファイルの本文（作業ルール）を編集

変更をコミットすれば、チーム全員に同じ設定が配られます。

## 別のユーザー・別のマシンで使うには

1. リポジトリをクローンする
2. `cd drug-and-oath` でセッションを開始する
3. `/model` で Fable を選ぶ（メイン会話のモデルだけは各ユーザーの設定）

これだけです。`.claude/agents/` はリポジトリに入っているので、
ワーカーの定義・モデル割り当て・作業ルールは自動で共有されます。

> **注**: メイン会話のモデル（Fable）だけはリポジトリから強制できません。
> 各ユーザーが `/model` で一度選べばデフォルト保存されます。

## コストと使い分けの目安

サブエージェントは毎回コンテキストをゼロから読み直すため、起動コストがあります。
以下を目安に使い分けてください:

| 状況 | 推奨 |
|------|------|
| 1〜2ファイルの小さな修正 | Fable が直接やる（委譲しない方が速い） |
| 独立した定型タスクが複数ある | implementer に並列委譲 |
| 設計判断を伴う大きな機能 | senior-implementer に委譲 |
| 戦略・計画・ドキュメント立案 | Fable が直接やる |

## トラブルシューティング

| 症状 | 対処 |
|------|------|
| エージェントが一覧に出てこない | セッションを `drug-and-oath/`（Git リポジトリ側）で起動しているか確認 |
| ワーカーが文脈を知らずに変な作業をする | 委譲プロンプトに受け入れ条件と対象ファイルを明記する（Fable の責任） |
| モデル指定が効いていない | `.claude/agents/*.md` の frontmatter の `model:` 行を確認 |
