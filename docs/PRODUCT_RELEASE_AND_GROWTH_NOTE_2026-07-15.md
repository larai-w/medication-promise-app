# おくすりの約束: 公開判断・MVP・ユーザー拡大戦略ノート

作成日: 2026-07-15

このノートは、ブログ制作に伴って話した一般公開の判断、MVPの定義、ユーザー範囲の広げ方を記録する。

## 結論

- **アプリはまだ一般公開しない。** Webは共有アクセスコードで保護したが、WebとAlexaが共通の `default-user` を使う設計のため、対象は開発者が管理する一世帯に限る。
- **ブログは内容によって先に公開できる。** 介護や服薬記録の課題を扱う読みものは公開可能。ただし、一般利用できるように見せるCTAは置かず、「開発中」「限定テスト中」と明記する。
- 検索流入から利用につなげる製品紹介記事は、少なくとも限定テスターの募集ページ、プライバシーポリシー、データ分離が整ってから公開する。
- ユーザー像は将来広げる。ただし、**いま広げるのはインタビュー対象であり、MVPの実装対象ではない。** 最初のMVPは「Alexaを使う一世帯」に絞る。

## 現在の一般公開ブロッカー

1. WebとAlexaの保存先が `default-user` 固定で、別の利用者を区別できない。共有アクセスコードは一世帯を閉じて試すための暫定ゲートであり、世帯分離ではない。
2. AlexaとWebの利用者を結びつけるアカウント連携がない。
3. Alexaの薬名と5つの時刻は環境変数で変更できるようになったが、世帯ごとに本人・家族が設定する画面はない。
4. Alexaインタラクションモデルの反映と、リマインダーを含む本番実機確認が完了していない。
5. プライバシーポリシーと利用条件は限定ベータ向けの案を公開した段階で、一般公開前の確認が必要。

## 「MVP」を二段階に分ける

### MVP 0: 価値検証版（現在地、Webのアクセス保護まで完了）

対象は開発者の管理下にある一世帯。次の一連の体験が成立すれば、価値の核は検証できる。

1. Alexaが薬の時間を知らせる
2. 本人が声、家族がWebのタップで服薬を記録する
3. 今日飲んだかを画面で確認する
4. 一週間・一か月を振り返る
5. 月次PDFを相談時の材料にする

これは技術デモではなく、一世帯で「薬、飲んだっけ？」の確認負担が実際に軽くなるかを見る段階。

### MVP 1: 限定ベータ版

3〜5世帯に使ってもらうための最低条件。機能を増やす前に、以下を満たす。

#### 安全・プライバシー

- [ ] 認証があり、世帯ごとにデータが分離される
- [ ] Alexaの利用者とWebの世帯を安全に結びつけられる
- [ ] 他世帯の記録を取得・編集・削除できないことをテストする
- [x] 日本語のプライバシーポリシーと利用条件の限定ベータ向け案を公開する
- [x] データの保存内容、利用目的、削除方法を説明する
- [x] 「服薬確認を保証しない」「医療機器ではない」と明示する
- [x] 服薬記録だけを根拠に、受診・看護師への連絡・服薬判断を勧めたり控えさせたりしない
- [ ] リマインダー作成時に目的と件数を伝え、利用者の明確な依頼・同意を得る

#### 中心体験

- [x] 朝・昼・晩・夜8時・夜9時をAlexaとWebの両方で記録できる
- [ ] リマインダーの同意・権限付与・再設定が実機で完了する
- [x] 記録の編集・削除ができる
- [x] 一週間・一か月の表示とPDF出力ができる
- [ ] エラー時に利用者が次に何をすればよいか分かる
- [ ] 薬名と服薬時刻を世帯ごとに設定できる、または固定対象であることを明確に説明する
- [x] コードに固定された「レボドパ」を、一般利用者へ誤って案内しない

#### 運用

- [ ] エラーを検知でき、問い合わせ先が表示される
- [ ] バックアップと復旧方法が決まっている
- [ ] Alexaの主要な発話を実機とシミュレーターで確認する
- [ ] 重大な不具合時に公開を止める手順がある

## 一般公開のゲート

次をすべて満たしたら、Webの一般公開とAlexaスキルストア公開を判断する。

1. MVP 1の安全・機能・運用条件を満たす
2. 3〜5世帯が最低2週間利用する
3. 他人のデータが見える事故が0件
4. 主要操作の失敗や、意味の分からないAlexa応答を修正済み
5. 少なくとも3世帯が2週目も継続して使う
6. 「確認の回数が減った」「記録が以前より楽になった」など、価値を示す具体的な声が得られる
7. 日本語のプライバシーポリシー、問い合わせ先、削除手順が公開済み
8. AlexaのValidationと必要なテストを通し、認定を取得する

Amazon Alexaでは「認定してすぐ公開」と「先に認定し、公開は後で行う」を選べる。準備が整った段階で後者を使い、公開日をこちらで制御するのが安全。

## ブログの公開戦略

SEO目的でも、検索エンジン向けに似た記事を量産しない。読者の異なる困りごとに、それぞれ一つの明確な答えを返す。

### 今から公開できる

- 介護者が薬の時間を覚え続ける負担
- 服薬記録が続かない理由
- 声で記録することの意味
- 診察時に記録を振り返る考え方

記事末尾は「現在開発中」「一般公開前」とし、製品ページの紹介までに留める。公開アプリへ直接誘導しない。

### 限定ベータ開始後に公開する

- 実際の使い方
- Alexaの設定手順
- テスター募集
- 利用者の声や導入事例（明確な同意を得たもの）

### 一般公開後に公開する

- 利用開始までの完全ガイド
- よくある質問とトラブル解決
- Alexaスキルストアへの導線を持つ記事
- 実データを匿名集計した継続利用・改善の報告

Googleは検索順位だけを狙ったコンテンツではなく、既存・想定読者に実際に役立つ people-first content を推奨している。VEAI LAB.の強みは、介護経験から生まれた具体的な課題と設計判断を書くことにある。

## ユーザー範囲を広げる順序

### 第1段階: 一世帯

- 主な導入者: 40〜60代の家族介護者
- 主な利用者: Alexaを使う高齢の親・家族
- 課題: 一日複数回の薬を「飲んだか」確認する負担
- 成功: 本人が声で記録し、家族の確認回数が減る

現在の既定時刻は、この一世帯で価値を確かめるための設定として扱う。薬名は未設定時に一般的な案内になる。いずれも一般向け製品では世帯ごとに設定可能にする。

### 第2段階: 3〜5世帯の限定ベータ

訪問看護師、ケアマネジャー、知人からの紹介で募集する。広告ではなく、セットアップを一緒に行い、毎週短い聞き取りをする。

確認するのは「機能が欲しいか」だけではない。

- 誰がリマインダーを設定するか
- 誰が記録するか
- 誰がWebで確認するか
- Alexaが聞き取れない言い方は何か
- 家族の確認行動が本当に減ったか

### 第3段階: 10世帯程度の招待制ベータ

限定ベータで中心体験が成立した後、紹介枠を広げる。ここで初めてSEO記事、テスター募集、Alexaストア認定を組み合わせる。

### 第4段階: 小規模な介護事業者

施設・訪問看護向けは別の製品要件になる。次が揃うまで本格的に売らない。

- 複数患者管理
- 管理者・記録者・閲覧者の権限分離
- 監査ログ
- 患者の同意管理
- セキュリティと個人情報保護のレビュー
- 施設単位の導入・退所処理

最初から個人と施設の両方を満たそうとすると、MVPが大きくなる。施設にはインタビューだけ先に行い、実装は個人・一世帯の価値が確認できてから進める。

## 現時点の優先順位

1. Alexaインタラクションモデルを本番反映し、一世帯で実機確認（人の操作が必要）
2. 一世帯で2週間使い、確認負担が軽くなるか測る
3. 認証・世帯分離・Alexaとのアカウント連携を設計・実装する
4. 薬名・時刻を世帯ごとに設定する方法を実装する
5. バックアップ、復旧、削除の運用を決める
6. プライバシーポリシーと利用条件を一般公開前に確認する
7. 3〜5世帯の限定ベータを実施する
8. フィードバックを反映し、Alexa認定を「公開は後で」で取得する
9. 一般公開判定後、製品紹介記事のCTAを公開利用へ切り替える

## 2026-07-15に自動で完了した安全対応

- 本番Webを16文字以上の共有アクセスコードと署名済みHTTP-only Cookieで保護
- 未認証APIを401、未認証画面をログイン画面へ転送
- 検索エンジンに `noindex` を指定し、`robots.txt` でも全クロールを拒否
- API入力の年月日・時刻・記録ID・メモ長を検証し、存在しない記録の更新を防止
- 限定ベータ向けプライバシーポリシー、利用条件、問い合わせ先を公開
- Alexaから特定薬名「レボドパ」の固定文言を除去し、設定可能化
- 夜9時の応答から看護師への連絡を控えさせる可能性のある文言を除去
- Alexa LambdaとWebを本番へ反映し、非破壊のスモークテストを実施

これらはMVP 0を安全に試すための対応であり、複数世帯向け認証・データ分離の代わりではない。
