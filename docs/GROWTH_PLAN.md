## なぜ大企業営業を今やってはいけないか

大企業（大手介護施設グループ・病院チェーン）への営業は魅力的に見えるが、今のフェーズでは確実に時間を無駄にする。

**現実の障壁**:
- 調達プロセスが6〜18ヶ月かかる
- セキュリティ審査・個人情報保護法対応が必要
- マルチユーザー認証がまだない（現状 USER_ID 固定）
- ISMS認証・SLA保証を求められる
- 担当者が変わると最初からやり直し

**代わりに狙うべき**: 定員29人以下の**小規模グループホーム**や**訪問看護ステーション**。意思決定者が現場にいて、導入判断が1〜2週間で出る。

## Phase 1: 0→10人（約2〜3ヶ月）

### 戦略: 信頼ファースト

日本の医療・介護領域では「知り合いが使っている」が最強の説得材料。
紹介者が医療専門家であれば、家族介護者はほぼ確実に試してくれる。

### ターゲットペルソナ（この順番で攻める）

```
1. 訪問看護師・ケアマネジャー（紹介者になってもらう）
   ↓ 紹介
2. 在宅介護している家族（直接ユーザー）
   ↓ 本人が使い始める
3. 高齢患者本人（Alexa で記録）
```

### 具体的な獲得アクション

**Week 1〜2: 「0→3人」**
- 医療関係者の知り合いに直接連絡して、患者・家族を1名紹介してもらう
- 紹介してくれた医療従事者本人にもアカウントを作って様子を見てもらう
- セットアップを代わりにやってあげる（Alexa の設定含め）

**Week 3〜4: 「3→7人」**
- 最初の3人からフィードバックをもらい、すぐに対応する
- 対応した内容を note に「開発日記」として投稿する
- 最初のユーザーに「使ってみてどうでしたか？」を聞いて証言（testimonial）をもらう

**Week 5〜8: 「7→10人」**
- Alexa スキルストアに公開申請（審査に2〜4週間かかる）
- X（Twitter）で「#介護 #服薬管理」のタグで発信開始
- 介護者向けの Facebook グループ・LINE グループに参加してコミュニティを観察

### Phase 1 での絶対NG
- アプリが未完成なのに広告を出す（悪い口コミが広まる）
- 10人が揃う前に機能追加に集中しすぎる
- 大企業に営業する（時間の無駄）

## Phase 2: 10→30人（約3〜6ヶ月）

### 戦略: 紹介を仕組み化 + チャネル多様化

**10人の時点で確認すべきこと**:
- [ ] 週に1回以上使っている人が何人いるか？（エンゲージメント確認）
- [ ] どのタイミング（朝/昼/晩など）が一番よく記録されているか？
- [ ] 「これがあると困る」という点は何か？

この3つに答えてから次のチャネルを開く。

### 具体的な獲得アクション

**コミュニティ戦略**:
- 在宅介護の Family Caregiver コミュニティに開発者として参加
- 「家族の介護に役立てているツールを公開しました」という投稿（宣伝ではなく共有）
- 介護者の悩みに丁寧に答えることで信頼を積み上げる

**Alexa スキルストア経由**:
- スキル説明文を「在宅介護」「服薬記録」「飲み忘れ防止」のキーワードで最適化
- 最初の10人にレビュー投稿をお願いする（★4以上が揃うと検索上位に来る）
- Alexa ユーザーは65歳以上の親を持つ40〜50代に多い → このアプリにドンピシャ

**note での情報発信**:
- 月1本のペースで「在宅介護と服薬記録」「Alexaで高齢の親の服薬を管理した話」などを投稿
- 自分の親や家族の介護経験を交えたストーリーは読まれやすい
- note は医療・介護系の読者が多く、SEO効果も高い

**小規模施設へのアプローチ**:
- 10人達成後、地元のグループホーム（5〜10施設）に直接訪問か電話
- 「無料で3ヶ月試してほしい。フィードバックをくれれば機能を追加する」
- 1施設でも入れば、そこから口コミが広がる

## 大企業vs中小施設 判断マトリクス

```
                  意思決定速度
                速い ←───────→ 遅い
      高い │ 小規模グループホーム    │ 大手介護施設グループ
 予算規模   │ 訪問看護ステーション    │ 病院チェーン
      低い │ 個人（在宅介護家族）   │ 行政・自治体
```

**結論**: 右側（大企業・行政）は今やらない。左上（小規模施設）が最初のB2B狙い目。

### 大企業営業に切り替えるトリガー条件

以下が全て揃ったら初めて大企業を検討する:

- [ ] MAU 100人以上（スモールビジネスでの実績）
- [ ] 認証・マルチユーザー・監査ログが実装済み
- [ ] セキュリティ診断（脆弱性検査）完了
- [ ] 3ヶ月以上の稼働実績・SLA ドキュメント
- [ ] 個人情報保護方針・利用規約の法的整備

## ユーザー獲得コスト試算

| フェーズ | 想定CAC（顧客獲得コスト） | 主なコスト |
|---------|----------------------|----------|
| 0→10人 | ¥0〜¥500/人 | 交通費・食事代のみ |
| 10→30人 | ¥500〜¥3,000/人 | note有料会員・SNS広告少額テスト |
| 30→100人 | ¥1,000〜¥10,000/人 | 施設営業コスト・広告費 |

**重要**: 個人紹介経由のユーザーはCAC ¥0 だが、LTV（生涯価値）は最も高い。
最初の10人の質（継続率・紹介率）が以後の成長を決める。

## よくある失敗パターン（このフェーズで避けるべきこと）

1. **機能を作りすぎる**: 10人のうち何人が実際に使っているかを確認しながら作る
2. **広告を先に使う**: 口コミが積み上がる前に広告を出しても費用対効果が最悪
3. **大企業を先に狙う**: 1社の契約を取るのに12ヶ月かかり、その間に個人ユーザーを100人取れた
4. **SNSに時間をかけすぎる**: フォロワーが増えても実際に使ってくれる人は少ない
5. **アプリの質より数を優先する**: 「30人いるが誰も毎日使っていない」は意味がない
